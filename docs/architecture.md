# SpecGap 技术原理

[返回项目首页](<../README.md>) · [使用指南](<dsh-plugin.zh-CN.md>)

## 定位：证据工作台，不是新的测试引擎

SpecGap 将需求、提交对象、模型判断和人工处理分层。它并不运行被审项目，也不靠 AST 或字符串匹配独立判断业务正确性。插件使用 DSH 的原生模型路由；CLI 则支持离线 Agent 导入或显式启用的兼容接口。

## 系统结构

```text
DSH 原生 React 客户端
  工作区 / 三步准备 / 问题与映射 / 冻结原文 / 人工处理
                 │ owner-only native Connection
                 ▼
Node ESM Host
  工作区边界、工具诊断、原请求恢复、任务生命周期、模型确认与审计
                 │ 隔离 Python 子进程 / 有界协议
                 ▼
Python bridge + dependency-free core
  Git/需求快照、AST、严格 review 校验、事件历史、中文报告
                 │
                 ▼
profile 私有 data/specgap（在被审工作区之外）
```

Host 使用原生 Connection 的 action/report 路由，不把这些接口注册为 Agent/MCP 工具。Python 进程的 `-I -S -B` 参数用于隔离导入等环境，不构成 OS 沙箱。

## 1. 比较范围与需求冻结

- 指定显式基线时比较基线到 head；指定目标分支时默认取目标/head 的 merge-base 到 head；两者都没有时使用 head 的第一父提交。
- 只读取已提交 Git 对象，不包含未提交或未跟踪文件；脏工作区提示不等于已纳入审查。
- 需求按段落、列表、显式 ID 保留文本及物理行号。它不是自动语义拆解器，不会把由 diff 反推的内容变成独立需求。
- 通过 name-status 变更清单识别新增、修改、重命名和删除，而不是先理解全部语义 diff。

## 2. 有界上下文选择

优先读取变更的 head、变更的 base，再补未改动的 head。默认 100 条/512 KiB，上限 2000 条/2 MiB；同文件两个版本分别计数。

Python AST 提供类/函数等结构及完整函数体范围。其他语言降级为文件级上下文。二进制、敏感名称、符号链接、子模块、解析失败与预算遗漏会显示限制。未找到证据有时只是材料不足，不能自动断定没有实现。

这里没有 embedding、向量数据库、RAG、微调、完整调用图或自主仓库探索。

## 3. 模型进行双向判断

一次有界请求要求同时覆盖：

1. **需求 → 实现**：每条需求是否有 head 证据支持，是否矛盾、缺失或不确定。
2. **变更 → 需求/意图**：每项变化是否能关联独立需求，或需要进一步澄清未声明行为。

插件先通过 DSH `llm.prepareCall` 固定路由、模型可见选项及准确请求，展示提供方、模型、推理等级和预算，再获取单次确认。确认有时限并绑定工作区、会话、run 和材料；变化后需重新确认。

准确请求先写入插件私有审计，读回并核验后才派发。默认最多 8192 输出 tokens、300 秒，服从更低的模型上限；不是精确费用上限。不执行模型工具调用，不自动付费重试。取消不保证撤回已发数据或费用。

## 4. 确定性证据校验

Python core 验证严格结构、冻结快照、完整且唯一的需求/变更覆盖，以及每项引用的：

```text
side + path + inclusive integer line range + exact quote
```

支持实现的证据必须来自 head，不能拿旧基线充当新实现。错误 ID、侧别、路径、行号或引文会被拒绝。但逐字吻合只证明材料存在，**不证明语义、可达性或推理成立**。

冻结原文阅读沿用这些来源，不跳转到后来变化的工作树；代码前后文各 10 行，全文每页 200 行。HTML/Markdown/代码按文本处理，不执行。

## 5. 人工流程与历史

implementation、intent、disposition、verification 四条状态轴分开。开发可回复，产品可批准意图变化，QA 可作缺陷处置和人工复验，安全角色可接受风险；这些角色全部是**本地自声明**。

复验通过必须有先前决议和非空 UTF-8 证据，附件最多 64 KiB。新的决议使旧复验不再是当前状态，但保留历史。工具不运行证据中的测试。需求/ref 变化后旧记录可读、拒绝写入；新代码需要新快照。

## 6. 存储、恢复与报告

快照、校验封装、前序哈希事件及幂等回执帮助保持读写一致和恢复原请求；不是恶意管理员无法篡改的账本，也不承诺任意故障下全局 exactly-once。

报告通过同工作区真实会话的原生侧栏展示，支持 Markdown 阅读/源码、JSON 树与检索，可见时约每 30 秒轮询同步。JSON 是公开审查视图，不是可导入备份。准确模型请求的审计不在 Session 日志中。

最终状态始终明确：

```json
{"assurance":"local_attestation_only","release_approval":false}
```

更多风险与适用范围见[安全说明](<../SECURITY.md>)。
