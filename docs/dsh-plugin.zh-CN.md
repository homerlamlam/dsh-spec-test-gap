**dsh-spec-test-gap 0.2.0-alpha.5** 是首次正式公开预发布：公开仓库、插件包与界面展示名统一更名，保留需求出处与冻结代码阅读等既有能力，仍是本地实验版。alpha.4 仅有公开源码标签，无正式 Release，未公开分发对应安装包。

**查看来源：** 问题的需求关联、需求映射与变更映射均显示原文路径/行号，点击「查看冻结原文」可定位高亮。代码证据可展开前后各十行，或点击「查看冻结全文」按每页 200 行浏览；「定位引用行」返回引用，「关闭原文」回到入口。文件来自审查冻结副本，展示对应基线/分支的提交与内容哈希，不读取当前工作树，也不伪造远程链接。旧记录只要包含完整来源即可使用；来源缺失或不匹配时保留引用并提示。链接仅用于审查内部导航，不是跨会话分享地址。

新增示例的需求、问题、测试建议与演示回复，以及报告标题、状态和说明统一中文。模型请求明确约束人类可读字段使用简体中文，但未实际调用提供方验证语言遵循效果。代码引用、机器字段及历史记录不翻译覆盖；需要保留的非中文原文在代码块中展示。升级后重新创建离线示例即可体验，不会自动重写旧示例。

独立 Python CLI/core 仍为 **0.1.0**，协议仍为 **1**。Python 模块/CLI 命令 `specgap`、源码目录 `plugins/dsh-specgap`、数据/API 命名空间 `specgap` 是保留的兼容内部标识，不应替换为公开品牌名。这是 GitHub 实验性预发布，不是自动测试运行器或发布批准。

源码/打包测试、实际界面操作与模型有效性是不同的验证层次；[本版验证记录](https://github.com/homerlamlam/dsh-spec-test-gap/blob/main/docs/verification.md)列出本次实际结果与未验证范围。[实际生产组件离线截图](https://github.com/homerlamlam/dsh-spec-test-gap/blob/main/docs/screenshots.md)来自本版离线预设 fixture，不是 AI 发现或已登录 DSH 的完整端到端验收。

## 环境、安装与升级

- 精确支持 **DSH 0.2.2-rc.1**，Node **>=24.9.0**，另需已安装 Python **>=3.11**、Git **>=2.31**。没有运行时 npm/Python 第三方依赖，不静默下载解释器。
- 仅面向**本机所有者**；仓库必须位于已注册工作区的规范化根目录内。不支持 LiveShare/非 owner。知道 run ID 不等于获得权限。
- Python/Git 必须能从 **DSH 进程环境**中的可信绝对目录找到，并位于被审工作区之外。不支持 shell 别名或项目内可执行文件。本 alpha 没有解释器选择 UI；测试用环境变量不配置已安装插件。诊断失败时请宿主操作者检查工具和环境，不要在面板输入命令，也不要自动改 profile/PATH 或重启。
- 数据位于 profile 自有 `data/specgap`，必须在被审工作区之外。不要把 profile/data 的祖先注册为被审工作区。记录含源码，请保护本地访问权限与备份。

### 从 GitHub Release 安装

1. 从 [0.2.0-alpha.5 预发布](https://github.com/homerlamlam/dsh-spec-test-gap/releases/tag/plugin-v0.2.0-alpha.5) 下载 `dsh-spec-test-gap-0.2.0-alpha.5.tgz` 与 SHA-256 清单，核对文件摘要。标签为 `plugin-v0.2.0-alpha.5`。
2. 打开现有 DSH GUI 左侧 **插件 → 添加插件**，在 **包名或地址** 输入包在 **Host 本机**的绝对路径，不输入 shell 命令或额外引号。
3. 点击 **安装**，完成后核对名称 **dsh-spec-test-gap**、版本 **0.2.0-alpha.5** 与兼容要求，再点 **立即启用**。只关闭对话框会留下已安装但未启用的包。
4. 检查警告及实际激活结果，按宿主 `application`/`nextStep` 指示处理。刷新**同一已认证页面**，在导航打开 **dsh-spec-test-gap**；公开展示名为 **dsh-spec-test-gap**，中文副标题为 **需求与代码双向对照测试助手**。

PowerShell 校验示例（替换成自己的下载位置）：

```powershell
Get-FileHash -LiteralPath 'C:\Downloads\dsh-spec-test-gap-0.2.0-alpha.5.tgz' -Algorithm SHA256
```

本次不通过 npm/PyPI 发布；不要把源码仓库根地址或未发布的 npm 名称作为安装地址。不要豁免版本兼容限制，也不要批准意外安装脚本。安装影响**当前 profile 的所有会话**。

### 升级、禁用与卸载

第三方本地包在当前 DSH UI 中通过**卸载旧包，再安装新包**升级；本地 tgz 没有注册表版本更新入口。先保护已有记录，卸载旧 SpecGap 插件（`@specgap/dsh-plugin`），再按上述步骤安装 `dsh-spec-test-gap`，不要把新旧插件同时启用并指向同一数据。

数据目录仍为 `data/specgap`，不要因更名删除、改名或自动清理。保留目录不等于完成备份，也不是自动迁移、完整恢复或升级兼容性的保证；报告 JSON 不是可导入备份。

禁用/卸载不保证删除持久运行/审计记录，也不能撤回已发模型请求。不要自动清理 profile 数据。仅在宿主要求并经用户同意后重启；无需启动替代服务。

## 先离线体验

1. 选择目标注册工作区；环境/能力详情按需展开。模型任务需要绑定同工作区的 live Session；这不代表外发许可。
2. 首页点击 **创建离线样例**：在插件存储内创建隔离 Git 样例，不修改用户仓库；三个预写 finding **不是 AI 输出或准确率证明**。真实项目按三步向导完成比较范围、需求与参与者、确认准备。
3. 新建审查：填写工作区相对仓库路径（根目录为 `.`），加载本地 refs，选择 head 和可选 target/base。不 checkout/fetch。有 target 默认 merge-base→head，否则默认 head 的父提交；根提交需显式 baseline。
4. 粘贴独立 Markdown/纯文本需求，或选择工作区相对需求文件。不要用 diff 反推的内容伪装需求真相。填写 actor 及 developer/product/qa/security 角色，冻结为**本地自声明**，不是登录身份认证。
5. 离线生成快照，只读取已提交对象，不纳入未保存/未提交内容。查看 H/T/M/B、脏/未知状态、遗漏与覆盖限制。默认 100 个上下文条目/512 KiB，上限 2000/2 MiB；需求 <=1 MiB。
6. 结果默认打开**问题列表和详情**，先看高风险问题、代码证据，再展开人工处理。需求→实现、变更→需求分别放在页签；版本哈希、限制与原文按需展开。逐字引用正确不代表推理正确或路径可达；HTML/脚本样文本只当数据。

## 不下载也能看报告

- 选择 Markdown 或 JSON 报告入口，明确确认切换到同工作区的一个驻留会话，报告在 DSH **原生右侧栏**打开。全局工作台与原生会话侧栏不能同屏，因此不会伪造工作台内的右侧栏。
- Markdown 支持阅读/源码；JSON 支持结构化展开与检索。复制和下载保留为可选操作，不是查看结果的前提。
- 侧栏独立从本地 Host 周期读取权威报告，不依赖已经卸载的工作台。展示最近成功同步时间、读取错误或过期提示；这不是推送协议，也不自动重试写操作或调用模型。
- 回到工作台继续当前审查，再次打开报告可以查看人工记录后的变化。JSON 仅为**公开审查视图**，不是可导入备份。报告仍可能含源码和需求，分享前检查敏感内容。

## 可选模型分析：每次单独确认

先预览准确生效请求、提供方/模型/推理等级与预算，再明确确认。离线准备/读取模型目录**不等于外发源码许可**。默认最大输出 8192 tokens、300 秒；模型较低限制优先。输入 <=8 MiB、输出 <=1 MiB；估算不等于精确 token/费用。

准确 system/messages/模板、模型可见选项、固定路由/预算及 attempt 绑定写入**插件私有逐次请求审计记录**，**不是 DSH 原生 Session 日志**，持久化成功后才经 `ctx.llm` 派发。不记录 API key 或私有传输配置。审计失败必须停止；已等待文件刷盘/重读，但 Windows 目录项不承诺跨所有硬件的断电持久性。哈希用于完整性，不是对本机管理员的身份认证或防篡改保障。

一次确认只授权一次尝试，不自动付费重试。材料/路由/预算变化须重新预览确认。取消等待所属资源结束，但无法撤回已发内容或费用。重启后未结算尝试标记 interrupted，不静默续跑。真实提供方与语义效果**未测量**；试跑需另行确认材料、提供方/模型及 token/时间预算。

## 人工操作、恢复与报告

- 选 finding、actor，并勾选本地自声明后回答；回答不是批准。
- 产品可批准意图变化；QA 可确认缺陷/判定非问题；安全可接受风险。仅 QA 可记录人工复验；passed 需要已有决议和非空 UTF-8 证据 <=64 KiB。插件不执行被审项目测试。新决议使当前复验失效，保留历史。
- implementation、intent、disposition、verification 分开。`ready_for_review` 不是发布批准；零 finding 不是正确性证明。
- 从历史重载并导出 Markdown。持久快照/事件是真相，浏览器状态不是。需求/refs 变化后旧记录可读但拒绝写入；新代码需新快照。
- 写操作丢回复时选择**恢复原请求**，不要发新操作。跨重挂载/工作区/Session 保留原 payload、key 和事件序号。含糊恢复 CONFLICT 不因读取成功而变成确定失败。有界“独立新快照”不取消/撤销旧写入。不要清空浏览器恢复存储来强行继续。

## 排障

| 现象 | 安全下一步 |
| --- | --- |
| 环境/能力不可用 | 保留诊断 ID，核对精确宿主版本、工具、live Session 和工作区外可写存储；不改运行时目录或伪造 SDK。 |
| 路径/ref/空输入错误 | 使用注册工作区内相对路径、已存在本地 ref 和非空独立需求。 |
| 模型/预算不可用 | 查看目录/预览，选可用路由或降低预算后重新确认；不隐式改全局提供方设置。 |
| JSON/证据非法 | 保留失败 attempt，修正离线审查或明确确认新尝试；不自动重试。 |
| STALE | 阅读/导出旧记录，再生成新快照；不重写历史。 |
| CONFLICT/丢回复 | 刷新读取并恢复原请求；仅在面板允许时确认“确定的初次冲突”，不为含糊请求生成新 key。 |
| 存储损坏/配额/未知锁 | 保留原字节与诊断 ID，停止写入，请操作者排查；不删锁、不改权威状态、不自动修复。 |
| GUI 入口缺失/旧版本 | 核对实际安装/激活版本、warnings/nextStep，刷新现有已认证页面；组件测试不是真实浏览器证明。 |
